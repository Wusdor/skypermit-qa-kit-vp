## 1. Скоуп
**In:**
- Auth и авторизация: регистрация (всегда `L1`), login/logout/me, `operator_id` из сессии, `401`/`403`, reviewer-or-owner чтение — `03-api-contract.md` §Authentication
- Реестр: operators, pilots, aircraft (+ list-расширения), уникальность, производные currency/weight band, отказ при `mtom_grams` > 30 000 г — `01-data-model.md`; `03` §Registry; `06` §1.2, §3
- Справочник зон (только чтение, 6 зон) — `03` §Reference data; `06` §4
- Заявки: create/list/get, `flight_purpose` ≤ 2000, фильтры — `03` §Flight requests; `01` §Time handling
- Гейт-пайплайн `PILOT`→`AIRCRAFT`→`ZONE`→`TIME_WINDOW`, первый провал, тело `422`, `rule_reference` — `03` §422, §Gate pipeline; `06` §1, §6 (с поправкой `07` п.1)
- `validate` без изменения состояния — `03` #13
- Машина состояний, дедлайн отмены, overlap — `02-state-machine.md`; `06` §1.4, §5
- Ревью: approve/reject, `ReviewAction`, note обязателен — `03` §Reviewer; `01` §ReviewAction
- `AuditLog` append-only — `01` §AuditLog
- Фронтенд: портал оператора, очередь ревьюера, контракт `data-testid`, отсутствие пре-фильтрации пикеров — `04-frontend-spec.md`

**Out:**
- Создание/изменение зон — нет эндпоинтов (`03` §Reference data)
- Повышение `authorisation_level` — out-of-band (`03` §Authentication)
- Аутентификация ревьюера — по дизайну её нет, только `X-Reviewer-Id` (`03` вводная)
- Связь `Aircraft.status = RETIRED` / `Pilot.status = INACTIVE` с гейтами — решено «нет» (№2); проверяем только, что они не валят гейты
- `SUSPENDED`-оператор (код/тело) — заблокировано №4; `APPROVED → COMPLETED` — заблокировано Q3

## 3. Стратегия
| Область | Уровень | Manual / Auto | Техники | Почему так |
|---|---|---|---|---|
| S1 Auth и доступ (роль × ресурс × эндпоинт) | API | Auto | таблица решений, эквивалентные классы | Комбинаторно, регрессия |
| S2 Реестр, валидация, уникальность, производные поля | API + DB | Auto | граничные значения, эквивалентные классы | Детерминированно |
| S3 Гейты: каждое условие + порядок первого провала | API | Auto | граничные значения, таблица решений, pairwise для комбинаций | Ядро риска, полный перебор дёшев |
| S4 `validate` ≡ `submit` без побочных эффектов | API + DB | Auto | сравнительное тестирование | Детерминированно |
| S5 Машина состояний, ревью, `AuditLog` | API + DB | Auto | state transition | См. `state-machine-test-plan.md` |
| S6 Контракт ошибок (`400`–`422`, тело `422`) | API | Auto | проверка схемы | Контракт |
| S7 Сценарии оператора и ревьюера целиком | E2E | Auto (2–3 happy path) + Manual | сценарии | Сквозная проверка, минимум UI-тестов |
| S8 `data-testid`, пикеры без фильтрации, отображение причин отказа | UI | Auto (smoke) + Manual | чек-лист контракта | Видно только в UI |
| S9 Время: DST, полночь, часовой пояс зоны | API | Auto + Manual | граничные значения | Частично заблокировано Q4, Q5 |
| S10 Seed и справочные данные | DB | Manual (разово) + Auto | сверка с таблицей | Риск устаревших значений |

Порядок: S10 → S1/S2 → S3/S4/S6 → S5 → S7/S8. Exploratory: понятность `message` в `422` для оператора (`03` §422) и UX формы заявки.

## 4. Тестовые данные и окружение
- Зоны — `supabase/seed.sql`, сверенный с `06` §4; неактивная зона создаётся только прямой записью в БД (эндпоинта нет)
- Пилоты по всем `rating` и датам `certified_on` у границы 18 мес.; aircraft на каждой границе веса; операторы `L1`–`L3` (повышение уровня — только в БД)
- Время: окна относительно текущих часов сервера в UTC; даты у перехода на летнее/зимнее время для curfew
- Роли: 2 оператора, ревьюер (`X-Reviewer-Id`), анонимный; `SUSPENDED` — только для Q1
- Чтение БД: `audit_log`, `review_actions`, `flight_requests`

## 5. Критерии
**Вход:** окружение с проверенным seed (S10); доступ к БД; согласован способ задавать время для S3/S5/S9.
**Выход:** все граничные значения из `06` §1–§5 и строки `06` §6 покрыты; матрица доступа S1 и переходов S5 пройдена; нет открытых Critical/Major по R1–R8.
**DoD:** незаблокированные области пройдены; по Q1–Q12 тесты помечены «не определено» и не считаются пройденными; кандидаты переданы владельцу документации.
