# story-doc-check

Вход: `$ARGUMENTS` — ключ задачи Jira (например, `SKY-1`). Для каждого acceptance criterion найти, где он описан в Confluence, и присвоить один из трёх статусов.

## Источники

- Jira: `mcp__atlassian__getJiraIssue`, `cloudId` = `f13593f8-183f-4502-ba93-6d6babaac436` (`getAccessibleAtlassianResources` не вызывать), `responseContentFormat: markdown`. Взять раздел acceptance criteria из описания.
- Confluence: только пространство **SPD** (SkyPermit Docs), читать по ID через `mcp__atlassian__getConfluencePage` (`cloudId` тот же, `contentFormat: markdown`). `mcp__atlassian__searchConfluenceUsingCql` — только если нужной страницы нет в таблице.

| Страница | ID |
|---|---|
| 01 — Data Model | 229395 |
| 02 — State Machine | 458753 |
| 03 — API Contract | 491521 |
| 04 — Frontend Spec | 524289 |
| 05 — Open Questions | 360450 |
| 06 — Business Rules | 491542 |
| 07 — Clarifications | 557057 |
| 08 — UML Diagrams | 589825 |

Всегда читай «05» и «07»; остальные страницы — по сути критериев. Ссылка внутри страниц вида `docs/0N-*.md` означает страницу SPD с номером `0N`.

## Правила

- Источник — только страницы SPD. Пробелы не заполнять ни своими знаниями, ни кодом, ни первоисточниками (A-7, TSD-4, ZC-2026.1, OH-1 и т.п.), ни ссылками из задачи.
- «05» — единственный источник истины о том, решён ли вопрос. Если относящийся к критерию вопрос открыт там — «не описано».
- «07» главнее «06»: при расхождении действует «07».
- Формулировки задачи сопоставляй с терминами документации (например, для UI-задачи «перевірка заявки» = кнопка «Check before submitting» → `validate` из «04»). Если однозначного соответствия нет — «не описано» с пояснением.
- Противоречия между самими страницами SPD, которые задевают критерий, — тоже «противоречит».

## Статусы

Ровно три, без «частично» и «описан, если»:

- **покрыто** — указать страницу, раздел и короткую цитату (≤25 слов).
- **противоречит** — что именно и где, с цитатой.
- **не описано** — какой части нет и что говорит ближайшая страница.

## Как оценивать критерий

1. Раздели критерий на утверждения: условие, результат, значения, ссылки.
2. Для каждого утверждения определи статус по правилам выше.
3. Строка получает худший статус: **противоречит** > **не описано** > **покрыто**. В ячейке «Цитата / что не так» назови утверждение, которое определило статус.
4. Одна строка на критерий. Критерии не дробить и не объединять.

## Вывод

Язык русский. Только таблица и итоговая строка, без вступления и выводов:

| # | Критерий (кратко) | Статус | Где | Цитата / что не так |
|---|---|---|---|---|

Итоговая строка ровно в таком виде: `<KEY>: N критериев — покрыто a, противоречит b, не описано c`.

Если в задаче нет раздела acceptance criteria или задача не найдена — одна строка с этим фактом вместо таблицы.

## Чего не делать

Только чтение. Не готовить тестовые данные, не предлагать писать тест-кейсы или комментарии в Jira, не изменять Jira и Confluence.
