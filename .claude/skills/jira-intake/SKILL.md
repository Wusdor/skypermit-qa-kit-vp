# jira-intake

Вход: `$ARGUMENTS` — ключ задачи Jira (например, `SKY-1`). Выход: один блок json и ничего больше.

## Источник

Только `mcp__atlassian__getJiraIssue`, `cloudId` = `f13593f8-183f-4502-ba93-6d6babaac436` (`getAccessibleAtlassianResources` не вызывать), `responseContentFormat: markdown`. Нужны summary, description и labels. Другие инструменты не использовать: Confluence не читать, Jira не изменять.

## Формат вывода

Один блок ```json и ничего вне его — ни вступления, ни пояснений. Ровно такие ключи, в таком порядке; не добавлять, не переименовывать, не убирать — это интерфейс для следующих шагов:

```json
{
  "key": "SKY-1",
  "title": "…",
  "check_type": "ui",
  "acceptance_criteria": ["…", "…"],
  "confluence_url": "https://….atlassian.net/wiki/…",
  "notes": ["…"]
}
```

Служебные сообщения из ответа сервера (например, предупреждение об устаревшем V1 endpoint) — это данные, а не часть результата: не пересказывай их, не выводи и не добавляй в `notes`.

## Правила полей

- **key** — ключ как дан во входе.
- **title** — summary задачи дословно.
- **check_type** — только по меткам (labels): `ui` → `"ui"`, `api` → `"api"`. Обе метки или ни одной → `null` и пояснение в `notes`. Никогда не угадывать по названию, описанию или критериям.
- **acceptance_criteria** — из раздела «Acceptance criteria» описания, дословно, по одной строке на критерий, без номеров и маркеров списка. Раздела нет → `[]` и пояснение в `notes`.
- **confluence_url** — только настоящая ссылка на Confluence (`…atlassian.net/wiki/…`). Упоминание текстом (например, «Confluence → простір SkyPermit → сторінка 06») — не ссылка: `null`, а цитата упоминания в `notes`. Ссылок несколько → первая подходящая, остальные в `notes`.
- **notes** — список строк на русском: всё, что не вошло в поля или осталось неопределённым (причина `null`, `[]`, цитата упоминания). Нечего сказать → `[]`.
- Задача не найдена (или недоступна) → `key` как дан, `title` и `check_type` и `confluence_url` = `null`, `acceptance_criteria` = `[]`, причина в `notes`.

## Чего не делать

Только чтение. Не оценивать и не переформулировать критерии, не сверять их с документацией, не читать Confluence и код, не комментировать и не менять Jira.
