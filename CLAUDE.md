# CLAUDE.md

Язык работы — русский: общение, тест-планы, тест-кейсы и прочий testware пишутся на русском. Идентификаторы из документации (имена сущностей, полей, статусов, эндпоинтов, кодов гейтов) не переводятся.

## Назначение репозитория

QA-кит для проекта SkyPermit. Основная работа — генерация testware (тест-планы, тест-кейсы) по документации SkyPermit. **Автотесты в этом репозитории не пишем.** Сборки, линтера и тестового раннера здесь нет.

## Источники

1. **Основной источник требований — `../skypermit/docs/`** (8 файлов):
   - `01-data-model.md` — модель данных
   - `02-state-machine.md` — машина состояний
   - `03-api-contract.md` — API-контракт
   - `04-frontend-spec.md` — спецификация фронтенда
   - `05-open-questions.md` — канонический статус открытых вопросов
   - `06-business-rules.md` — бизнес-правила
   - `07-clarifications.md` — обоснования принятых решений по вопросам
   - `08-uml-diagrams.md` — UML-диаграммы
2. **Код приложения (`../skypermit/`) — только oracle**, когда в документации пробел: по нему можно уточнить фактическое поведение, но поведение кода не становится требованием само по себе. Если тест-кейс опирается на код, а не на документацию, указывать это явно (файл/путь).

## Жёсткие правила

- **Ничего не изменять в `../skypermit`** — только чтение.
- **Не выдумывать требования.** Если в документации пробел или вопрос не решён, так и писать в testware (например, «ожидаемый результат не определён») со ссылкой на `../skypermit/docs/05-open-questions.md` (номер вопроса / раздел). Если статус-код или формат ответа не определён (например, вопрос №4 про `SUSPENDED`), не брать их по аналогии с похожими эндпоинтами из `03-api-contract.md`.
- `05-open-questions.md` — единственный источник истины о том, решён ли вопрос; `07-clarifications.md` объясняет, *почему* решено именно так.
- Если `07-clarifications.md` расходится с `06-business-rules.md`, действует `07-clarifications.md`.
- Ожидаемые результаты в тест-кейсах трассировать к конкретному документу и разделу.

## Структура

- `test-plans/` — тест-планы.
- `test-cases/{module}/` — тест-кейсы, сгруппированные по модулю.
- `.claude/skills/` — скиллы для генерации testware.
- `.claude/agents/` — появится позже.
