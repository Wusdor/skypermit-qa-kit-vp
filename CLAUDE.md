# CLAUDE.md

Язык работы — русский: общение, тест-планы, тест-кейсы и прочий testware пишутся на русском. Идентификаторы из документации (имена сущностей, полей, статусов, эндпоинтов, кодов гейтов) не переводятся.

## Назначение репозитория

QA-кит для проекта SkyPermit. Основная работа — генерация testware (тест-планы, тест-кейсы) по документации SkyPermit. **Автотесты в этом репозитории не пишем.** Сборки, линтера и тестового раннера здесь нет.

## Источники

1. **Основной источник требований — Confluence**, сайт `vp-skypermit` (cloudId `f13593f8-183f-4502-ba93-6d6babaac436`, `getAccessibleAtlassianResources` не вызывать), пространство **SkyPermit Docs, ключ `SPD`** (8 страниц). Читать через MCP-сервер `atlassian` (`mcp__atlassian__*`, не плагин), по ID страницы:

   | Страница | ID | Содержание |
   |---|---|---|
   | 01 — Data Model | 229395 | модель данных |
   | 02 — State Machine | 458753 | машина состояний |
   | 03 — API Contract | 491521 | API-контракт |
   | 04 — Frontend Spec | 524289 | спецификация фронтенда |
   | 05 — Open Questions | 360450 | канонический статус открытых вопросов |
   | 06 — Business Rules | 491542 | бизнес-правила |
   | 07 — Clarifications | 557057 | обоснования принятых решений по вопросам |
   | 08 — UML Diagrams | 589825 | UML-диаграммы |

   Номера и содержание совпадают с бывшими файлами `../skypermit/docs/01–08`. Ссылка внутри страниц вида `docs/0N-*.md` означает страницу Confluence с тем же номером `0N`. Локальная папка `../skypermit/docs` источником требований больше не является.

   **Исключение:** `scripts/uncovered-rules.mjs` не умеет ходить в MCP и по-прежнему читает локальные `../skypermit/docs/06-business-rules.md` и `07-clarifications.md`. Риск: локальная копия может разойтись с Confluence, и тогда список непокрытых правил будет неверным. Перед использованием результата `cover-gaps` сверять «06 — Business Rules» §6 и «07 — Clarifications» с Confluence.
2. **Код приложения (`../skypermit/`) — только oracle**, когда в документации пробел: по нему можно уточнить фактическое поведение, но поведение кода не становится требованием само по себе. Если тест-кейс опирается на код, а не на документацию, указывать это явно (файл/путь).

## Жёсткие правила

- **Ничего не изменять в `../skypermit`** — только чтение.
- **Не выдумывать требования.** Если в документации пробел или вопрос не решён, так и писать в testware (например, «ожидаемый результат не определён») со ссылкой на страницу «05 — Open Questions» (номер вопроса / раздел). Если статус-код или формат ответа не определён (например, вопрос №4 про `SUSPENDED`), не брать их по аналогии с похожими эндпоинтами из «03 — API Contract».
- «05 — Open Questions» — единственный источник истины о том, решён ли вопрос; «07 — Clarifications» объясняет, *почему* решено именно так.
- Если «07 — Clarifications» расходится с «06 — Business Rules», действует «07 — Clarifications».
- Ожидаемые результаты в тест-кейсах трассировать к конкретному документу и разделу.

## Структура

- `test-plans/` — тест-планы.
- `test-cases/{module}/` — тест-кейсы, сгруппированные по модулю.
- `.claude/skills/` — скиллы для генерации testware.
- `.claude/agents/` — появится позже.

## Новые скилы и агенты

- Дорогие пайплайн-скилы — `disable-model-invocation: true` и короткий `description` без триггерных фраз.
- `allowed-tools` узкие, с путями; деструктивные команды (`rm`) заранее не разрешать.
- Синтаксис frontmatter и правил разрешений сверять с документацией Claude Code.
- Пробный прогон пайплайна — только по просьбе пользователя.

## Git

- После законченной порции работы: `git add` нужных файлов → `git commit` с осмысленным сообщением на русском → `git push`. Коммиты домашнего задания воркшопа N начинаются с префикса «wsN: ».
- `git push` запускай отдельным вызовом Bash: не в цепочке через `&&` и без `cd`. Иначе sandbox не выпустит его в сеть.
- Перед push проверь `git status`: не должно остаться незакоммиченных и неотслеживаемых файлов, которые должны попасть в репозиторий (`.claude/settings.local.json` в `.gitignore` и не коммитится).
- Force-push, `--mirror` и удаление веток запрещены.
